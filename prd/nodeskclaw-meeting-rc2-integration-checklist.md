## 3. 必须先修复的代码问题

### R02：限流等待不能造成分页重头开始

相关位置：

- `app/services/rate_service.py:14–24`：额度未到时立即抛出 RATE_LIMITED，不等待。
- `app/integrations/tencent_meeting/client.py`：每次请求获取应用级额度，账户级录制列表另有限流。
- `app/services/content_service.py:93–105`：每次 fetch 新建内存收集器并从 pid=0 开始。
- `app/services/job_service.py:32–50,78–87`：领取作业增加 attempts；限流也计入有限失败重试。

离线复现只证明快速响应与默认限流组合下会失败，不宣称所有真实网络环境一定出现。网络延迟恰好足够长可能遮住问题。

修复要求：

1. 短时节流等待放在受控调度层，等待时不长期占用数据库事务锁，并维持 Worker 心跳。
2. 较长等待以 run_after 调度，区分正常延后与错误重试；不因健康分页耗尽作业预算。
3. 保留完整性语义：继续处理腾讯 pid 的包含式分页、重叠去重和内容变化；重启不能发布半份转写。
4. 如采用检查点，必须同时保存足够的已获取内容及版本信息，不仅保存一个游标。
5. 创建写操作在真正发送前完成额度准入，区分未发送与结果不确定；不能以修复限流为由自动重试不确定写入。

验收：默认 0.2 秒间隔下至少三页转写完整完成；至少 20 页录制元数据同步不因正常节流失败；两个 Worker 合并流量不超配置额度；重启仍不重复发布。

不能直接删除限流：腾讯账户级录制列表官方限制为 10 次/分钟。[S1]

### R03：OAuth 临时刷新失败不等于授权已失效

相关位置：`app/services/connection_service.py` 的 `oauth_credentials()`，尤其 broad `except Exception`。

当前网络超时、暂时服务不可用、错误返回解析异常都可能把连接写为 REAUTH_REQUIRED。结果是一个原本可能自动恢复的连接退出正常维护状态。

修复要求：按明确的上游原因分类，超时、5xx、分钟限额等采用可恢复状态与退避重试；保存现有加密 refresh token。明确的 refresh token 过期、被撤销等才要求用户重新授权。异常身份或合同错误采用安全阻断状态并报警，不盲目重试，也不错误声称用户撤销授权。并发刷新锁与新令牌原子更新保留。

验收：第一次刷新超时、下一次成功时自动恢复；真正失效才重新授权；双 Worker 只进行受控刷新；日志没有令牌。

### R04：错误类别决定后续动作

相关位置：`app/integrations/tencent_meeting/client.py:48–65`、`app/core/errors.py`、`app/services/job_service.py`、`app/services/diagnostic_service.py`。

建议按操作和鉴权模式分类，不单凭 HTTP 状态码。以下是此次重点：

| 错误 | 应表达的原因 | 建议行为 |
|---|---|---|
| 190303 | AK/SK 凭证或 OAuth 身份/访问令牌校验问题 | 按当前通道定位；禁止换管理员连接兜底 |
| 190325 | OAuth 接口不支持或授权 scope 不足 | 明确提示检查能力与授权范围 |
| 190300 | 请求时间与服务端偏差 | 检查 NTP、秒单位与签名时间 |
| 190311 / 190312 | 总接口 / 单接口日限额 | 不按固定每分钟重试；进入日配额受限状态 |
| 30003（转写） | 内容仍生成中 | 标记 CONTENT_NOT_READY，按内容就绪重试 |
| 30002 / 30001（转写） | 无内容 / 转写不存在 | 明确与生成中、服务不可用区分 |

官方错误含义见 [S2][S3]。对外保留安全、稳定的业务错误；管理员诊断可包含脱敏上游错误码、操作名、状态码、关联 ID 和耗时，不能输出完整带敏感信息的原始报错或请求正文。

注意 `app/core/errors.py` 当前通过排序生成数字错误码，新增原因时应防止已有错误码整体移动，先冻结对外映射。

## 4. 诊断与真实联调工具

### R05：补齐逐层诊断，而不是再做任意 API 转发器

现有 `DiagnosticService.run()` 只接受 configuration、oauth_user_info、upcoming、transcript、minutes。配置诊断会展示 webhook_verified 等状态，但配置探测成功不证明真实资源可访问。

建议增加受权限控制的 history、records、corp_records、record_detail 探测与完整的连通状态展示。每项显示“未执行 / 通过 / 失败 / 等待上游生成”，不把一个配置检查合并显示为全部就绪。

推荐顺序：

```text
Backend 身份 → 应用凭证 → 操作者映射 → 基础列表
→ Webhook 验证 → STS 回调匹配 → 录制文件详情
→ 完整转写 → 指定模型纪要 → 受控下载
```

同步修复事件列表字段：Portal 当前使用 received_at/safe_summary，服务返回 created_at/summary。该项属于页面合同对齐，不涉及腾讯协议变更。

第一轮同一接口先由官方开发者调试工具进行人工诊断，再由网关以相同应用、同一操作者、同一会议调用。两者请求来源 IP 和应用可用范围分别检查；官方工具成功并不绕过内部员工权限。

## 5. 有基础实现，但端到端仍需完成

### R06：事件需要针对目标资源调度

`app/services/event_service.py` 已有验签后持久化、去重、Worker 处理；但大部分非 STS 事件主要将同步策略推进到立即执行并触发近期扫描，result 则留在摘要中。

问题：晚到的旧会议内容事件可能超出扫描窗口；收到消息不等于目标录制已经获取。

应将 recording.completed、smart.transcripts、smart.minutes 等解析到源连接及文件，按批准范围定向排队；目标尚未入库时通过允许的源查询发现，不通过消息参数越权创建任意资源。result=2 应明确失败或需诊断，不标记成功；删除事件要撤销本地可读状态。

验收：历史会议数日后产生纪要事件，能更新对应文件；重复事件不重复发布；错误结果不触发虚假 READY；Worker 重启可恢复。智能纪要事件明确区分成功与失败。[S4]

### R07：先验现有创建，再决定是否补自动录制参数

`app/services/operation_service.py` 已有创建准备、人工确认、幂等、后台执行与结果不确定处理；无需重新实现。当前 `MeetingCreate` 和请求映射未提供 `settings.auto_record_type` 等录制配置。

第一场测试可以由测试人员手动在腾讯客户端开启云录制及所需智能功能，不阻塞接口联调。要实现完全自动的“创建 → 录制结果”，再新增受控录制字段、企业策略校验和确认页显示，并将其计入参数摘要。禁止将任意腾讯 settings JSON 透传。

腾讯 auto_record_type=cloud 受企业账户配置约束；未填写时可能继承创建者设置。auto_asr 表示会中自动文字转写，不应据此承诺录制纪要一定生成。[S5]

### R08：真实下载验证

下载与 Range 处理已有实现，下一步重点为：真实上游返回的媒体域名、文件大小/类型、短期地址、上游允许下载状态、撤权后新下载与续传请求。

只加入实际允许的精确媒体域名；不取消 URL/地址安全校验。API 与 Worker 共享私有存储路径。不能将短期下载链接视为可以无限期传播的权限凭证，也不能承诺回收已经下载到下游的文件。

当前纪要读取与“腾讯原生纪要文件下载”不能混为一项能力；未实现的文件类型应明确返回不支持，不用生成内容冒充腾讯原始导出。

### R09：MCP 需要真实客户端测试

现有 HTTP/JSON-RPC 测试保留。`test_mcp_sdk_accepts_wire_contract` 实际是 HTTP 响应加 SDK 类型验证，不是完整 SDK ClientSession、授权发现和浏览器授权的端到端测试。

新增真正的远程客户端会话，验证握手、协议版本、工具枚举/调用、授权回跳、PKCE、令牌受众、撤销、会话重连以及 REST/MCP 权限一致性。Meeting 自建 MCP 调用已有腾讯 REST，不以腾讯官方 MCP 资格为这条测试路径的前置条件。

## 7. 配置清单：不是待开发功能

### 7.1 网关与 Backend

| 配置 | 填写原则 |
|---|---|
| DATABASE_URL | Meeting 独立 PostgreSQL 连接 |
| NODESKCLAW_BACKEND_URL | Meeting 容器实际可访问的 Backend 地址，不把容器 localhost 当宿主机 |
| BACKEND_SERVICE_TOKEN | 与 Backend 的 MEETING_IDENTITY_SERVICE_TOKEN 一致；不是 JWT_SECRET |

| PUBLIC_BASE_URL | 真正提供回调及网关服务的 HTTPS 地址 |
| PORTAL_BASE_URL | 员工确认和授权页面地址 |
| ALLOWED_HOSTS / CORS_ORIGINS / MCP_ORIGINS | 精确配置，不用通配符掩盖问题 |
| MEDIA_ALLOWED_HOSTS | 实测后批准的精确媒体域名 |
| STORAGE_PATH | API 与 Worker 共用的私有持久化目录 |

MEETING_ENABLED=true
MEETING_CREATE_ENABLED=false

### 7.2 两类腾讯应用

| 内容 | 企业级自建应用 | 现有第三方 OAuth 应用 |
|---|---|---|
| 凭据 | 企业 ID、应用 ID、SecretId、SecretKey | 企业 ID、应用 ID、客户密钥 |
| 身份 | 真实腾讯企业 userid；STS 使用有相应角色的管理员 | 员工独立 open_id 与授权连接 |
| 资源 | 只在允许的企业/操作者范围查询 | 按接口支持能力与员工实际 scopes 验证 |
| 回调 | 配置事件接收，订阅 STS 与录制相关事件 | 配置 OAuth 回跳和需要的事件接收 |
| 网络 | 腾讯白名单加入网关真实公网出口 IP | 同样核对网关出口及官方调试工具设置 |

腾讯第三方配置区分 OAuth 回调域名、H5 可信域名、API 来源 IP 白名单，三者不要互填。[S6]

由现有接口获取实际地址：

```http
GET /api/v1/admin/applications/{application_id}/setup
```

按其返回配置，不把腾讯应用 ID 替代网关内部 UUID：

```text
/callbacks/tencent/events/{receiver_id}
/callbacks/tencent/oauth/{application_id}
```

OAuth 的 open_corp_id 取授权返回值，不与控制台企业 ID 强行等同。当前程序会阻断未被批准的企业身份；管理员应先核验归属，再更新允许列表并重新授权、由员工确认，不应删除企业匹配检查。[S7]

### 7.3 内部身份与授权

先准备测试员工 A、B 和一个批准的企业采集操作者。member_id 使用 Backend 的组织成员 ID，不使用 User.id、姓名、腾讯 userid 或 open_id 代替。

配置内部调用客户端、员工操作权限、资源范围、身份映射、企业采集授权、内容保留策略。采集授权与员工阅读授权分别设置；应用管理权限不自动赋予全文访问权。普通员工 B 在未授权时应看不到 A 的目标资料。

## 8. 真实联调顺序与通过标准

| 阶段 | 动作 | 通过标准 |
|---|---|---|
| G0 环境 | 启动 API/Worker/PostgreSQL，完成 Backend 身份核验 | 健康检查与成员身份准确；不是只看到 /docs |
| G1 样本 | 准备一场非敏感会议，客户端可确认录制、转写和指定纪要已生成 | 有明确 meeting_id、record_file_id、所属用户与授权来源 |
| G2 AK/SK | 同一操作者查询已知列表及录制 | 找到预期资源；无签名/身份混用 |
| G3 Webhook/STS | URL 验证 → 请求 STS → 收回调 → 匹配 req_id → Worker 保存票据 | 敏感内容接口携带有效票据成功，而不仅生成接口返回成功 |
| G4 内容 | 获取完整转写、指定模型纪要；同步到本地并由员工读取 | 分页无漏段、状态可信、内容与原文件对应 |
| G5 OAuth | A/B 分别授权，校验企业、确认连接，查询各自有权资源 | 连接隔离、不会覆盖令牌、不会在失败时用 AK/SK 越权兜底 |
| G6 创建 | 开启创建能力，提交 → 人工确认 → 实际创建 → 人员入会录制 → 事件 → 获取结果 | 原会议与网关资源对应，幂等重试不重复创建 |
| G7 下载/MCP | 受控下载及真实智能体调用，做撤权/停用/越权测试 | REST 与 MCP 结论一致，下载权限不会被链接绕过 |

重要边界：

- G2 的账户级录制列表走 AK/SK，官方不支持 OAuth，且限制 10 次/分钟。[S1]
- OAuth 的“查询用户的会议列表”官方说明限定为 OAuth 创建的有效会议；这个接口返回空不能直接解释为授权失败或没有任何会议。企业客户端既有会议的集中采集优先用批准的企业通道。[S8]
- 腾讯回调验证要求 GET 在 3 秒内正确返回挑战明文；事件 POST 在 5 秒内返回 HTTP 200 和指定确认文本。先可靠入库后确认，再由 Worker 长时间处理。[S9]
- STS 接口返回 req_id；票据通过事件回调获得。记录二者关联，不把请求成功当票据就绪。[S10]
- 智能纪要需在上游功能可用且结果生成后取回；当前代码固定查询 llm=3 的 Markdown，验收应比较同类型纪要。元宝待办可包含在 minute 正文，todo 为空不代表失败。[S11]

## 10. 当前不必提前扩展

第一场联调不要求腾讯应用市场上架、会中 H5/JSAPI、腾讯官方 MCP 接入、周期会议/取消修改、OA 自动写入、文档翻译、知识库入库或 Kubernetes 高可用。先通过 REST 的真实读链路，再做创建回流，最后用 MCP 验同一权限链路。

首个可交付里程碑：**一场明确授权的真实会议，能够通过网关定位录制、获取完整转写和指定纪要；授权员工可读，未授权员工不可读；每一环节有脱敏诊断记录。**
