# nodeskclaw-meeting 第一版设计规格

## 0. 文档状态与阅读约定

**定位：腾讯会议应用接入与权限网关。** 本文将已经确认的架构方向细化为供评审的产品、服务、接口和安全规格，不是已经部署的系统说明，也不是代码实施完成报告。

用户已确认：采用 Knowledge / Task 的独立服务结构；以 Backend 为员工与组织身份来源；以 Meeting 为会议权限执行方；REST 与自建 MCP 共用业务服务；腾讯凭证集中托管；保留现有 OAuth 应用，并新增企业级自建应用，第一版同时接入两条通道。

本文中的字段、内部接口、页面、默认值和验收用例，除标注“现有实现”或“腾讯事实”外，均为**新增设计**。这些细节随本文评审确认；不能把对总体方向的确认当作已批准全部细节。

代码核验基线是上方 commit。核验覆盖 Knowledge / Task 架构说明、Knowledge 身份依赖实现、Task 依赖配置、Backend 现有成员上下文入口和 Portal 源目录；不声称已完成全仓安全审计。[R01—R07]

**交付边界：**本轮仅产生设计文件和配置联调清单，没有创建腾讯应用、修改真实权限、提交仓库、执行真实会议操作或运行新增业务测试。

### 0.1 术语

| 术语 | 本文含义 |
|---|---|
| Application（应用） | 腾讯后台创建的应用及其应用级配置 |
| Connection（授权连接） | 某应用下可实际用于调用腾讯接口的企业连接或用户授权连接 |
| Client（内部调用方） | OA、内部业务服务、Portal 或智能体宿主，不是腾讯应用 |
| Principal（调用主体） | 经可信认证得出的员工、智能体委托或系统主体 |
| Grant（授权记录） | 某主体的操作范围、资源范围及有效期 |
| Resource Origin（资源来源） | 某份会议资料通过哪条连接、哪种授权取得 |
| ACL（资源访问控制） | Meeting 对本地会议资源的访问规则 |
| STS-Token（临时票据） | 腾讯指定敏感接口使用的自建应用临时凭证 |
| MCP（模型上下文协议） | 本系统向智能体提供工具的协议；不等同于腾讯官方 MCP |

## 1. 目标、边界与第一版范围

### 1.1 业务目标

让内部系统只对接一个 Meeting 服务，即可在可审计的授权范围内查询会议、获取原生转写和纪要、下载资料、创建会议；让智能体使用相同能力，但不能扩大员工权限、取得腾讯凭证或自行批准高风险操作。

成功标准不是“签名通过”或“接口返回 200”，而是指定内部系统以指定员工或系统主体完成端到端业务，且负向越权用例全部被拒绝。

### 1.2 包含与不包含

| 第一版必须交付 | 第一版不交付 |
|---|---|
| 企业级自建应用与 OAuth 应用的独立配置 | 腾讯官方 MCP 上游接入及企业灰度申请代办 |
| AK/SK、OAuth、STS 生命周期管理 | 自建 ASR、基础 AI 摘要生成、媒体会议服务器 |
| 腾讯回调接收、可靠同步与补导 | 任务识别、文档翻译对比、OA 审批业务实现 |
| 员工身份映射、内部客户端与智能体授权 | 新员工账号系统、另一套组织主数据 |
| 会议元数据、原生转写、原生纪要与受控下载 | 腾讯应用市场公开上架、跨企业开放安装 |
| 一次性普通会议创建及受控代创建 | 周期会议创建、会中控制、修改及取消会议 |
| 内部 REST API 与真实 MCP 协议服务 | 任意 URL 转发、腾讯全量接口自动映射 |
| Portal 管理页面、诊断、审计 | 默认全企业全历史音视频复制 |
| 租户隔离和未来会中应用扩展边界 | 第一版完整会中 H5 / JSAPI 产品体验 |

第一版交付不依赖 Knowledge、Task 或 OA 服务在线；它们都是后续消费方。Backend 身份服务与 Meeting 自有数据库是必要依赖。

### 1.3 使用场景

| 编号 | 场景 | 完成结果 |
|---|---|---|
| UC-01 | 接入管理员登记两类腾讯应用 | 分别看到配置、授权、网络、回调、内容能力状态 |
| UC-02 | 员工绑定腾讯会议身份 | 绑定到可信 `member_id`，错误企业或身份冲突进入阻断状态 |
| UC-03 | 内部会话系统查询员工会议 | 返回可见会议及可执行动作，无权资源不进入列表与计数 |
| UC-04 | 内部系统获取会议结果 | 得到完整性可识别的原生转写/纪要，不必接触腾讯接口细节 |
| UC-05 | 员工下载会议资料 | 下载申请和实际取文件都经过授权校验 |
| UC-06 | 智能体协助预约会议 | 先形成待确认请求，经可信员工确认后执行一次 |
| UC-07 | 企业后台补导录制 | 使用单独的企业同步主体，采集权限不变成全员阅读权限 |
| UC-08 | 员工离职或授权撤销 | 后续请求、排队操作和新下载被拒绝，留下可核对记录 |

## 2. 已核实依据及其设计影响

### 2.1 仓库事实

| 依据 | 核实内容 | 本次采用方式 |
|---|---|---|
| Task 架构 [R03] | 根目录独立 Python 服务，自有数据库和 Alembic | 新增同级 `nodeskclaw-meeting/`，不合并到 Backend 进程 |
| Knowledge 架构 [R02] | 不自建员工账号，外部集成封装，成员身份由 Backend 返回 | Meeting 复用身份接入模式，不复制账号库 |
| Knowledge 身份依赖 [R04] | 将 Bearer 交给 Backend 获取成员上下文，缓存可关闭 | 不共享 Backend `JWT_SECRET`；新增 Meeting 专用契约 |
| Task 依赖 [R05] | Python 3.12、FastAPI、SQLAlchemy asyncio、asyncpg、httpx、uv 生态 | 同技术栈、同测试与打包习惯，独立锁依赖 |
| 开发约定 [R01] | 软删除、部分唯一索引、迁移、i18n、镜像平台要求 | Meeting 业务实体与发布流程遵循；敏感内容清理另列边界 |
| Backend 身份入口 [R06] | 存在 `knowledge-context` | 作为新增 `meeting-context` 的参考，不直接冒充会议权限接口 |
| Portal 源目录 [R07] | 已有 API、服务、路由、视图、国际化目录 | 在现有 Portal 增加会议模块，不新建前端项目 |

**不得照搬的实现细节：**某兄弟服务允许超级管理员绕过停用检查，并不代表 Meeting 可以给超级管理员默认正文权限；已有连接配置也不意味着生产数据库可以关闭 TLS。复用框架不等于无条件复制安全策略。

### 2.2 腾讯及 MCP 事实

| 依据 | 核实内容 | 设计约束 |
|---|---|---|
| 腾讯企业应用类型 [T01] | 企业级与应用级的数据范围不同 | 内部集中接入登记为企业级，仍核验具体操作者和资源权限 |
| 腾讯 OAuth 配置 [T02] | 客户密钥、授权回调域名、权限范围属于第三方应用配置 | 现有截图应用按已确认的 OAuth 通道登记；与 AK/SK 字段隔离 |
| 企业录制接口 [T03] | `GET /v1/corp/records` 不支持 OAuth，10 次/分钟、时间窗不超过 31 天 | 企业补导走 AK/SK；分窗口、分页并共享限流 |
| STS 生成 [T04] | POST 生成请求返回 `req_id`，票据通过回调接收 | 异步关联票据，不能把生成请求的成功当成已取得票据 |
| STS 事件 [T05] | `common.sts-token` 返回请求关联及票据信息 | 独立敏感处理路径，不写入可浏览的事件正文 |
| OAuth 鉴权 [T06] | 授权码、用户 Token、实际 scopes、应用内 open_id | 应用与用户连接一对多，密钥与用户 Token 只留服务端 |
| 转写详情 [T07] | 新建自建应用需要 STS；OAuth 无需同一 STS 流程 | 按接口、鉴权类型配置能力，不全局添加 STS |
| 回调服务 [T08] | GET 验证和 POST 事件响应格式不同 | 回调路由不套用业务 API 的统一 JSON 包装 |
| 原生纪要 [T09] | `/v1/smart/minutes/{record_file_id}`；元宝模式待办可在正文中 | `todo` 为空不能单独判定纪要失败 |
| 腾讯官方 MCP [T10] | 企业使用有独立开通条件，公开范围不等于企业全量数据 | 不作为本服务上游依赖 |
| MCP 固定版本规范 [T12、T13] | HTTP 授权受众校验、元数据发现、PKCE、协议生命周期 | 构建真实 MCP 服务，不将 REST 路由简单改名 |

本服务选择 MCP **2025-11-25 版本规范作为首版协议基线**，不是宣称它永远是最新版本。实现和验收只承诺经测试的客户端及协商版本。

## 3. 架构决策

### ADR-01：独立服务、同一仓库

`nodeskclaw-meeting` 自有 Python 环境、依赖锁、数据库账号、迁移和镜像。API/MCP 共享一个业务进程，后台 Worker 使用同一镜像的独立进程。首版不新增 Redis、Celery 或消息总线；可靠作业、分布式锁、事件投递使用 PostgreSQL。

允许共享数据库基础设施，但逻辑数据库、访问账号与数据所有权隔离。禁止跨库外键、直接修改 Backend 表或导入兄弟项目的 `app` 包。

### ADR-02：身份与业务授权分离

Backend 是组织与员工身份事实来源；Meeting 是会议授权和访问决策的唯一执行方。Portal 路由守卫只能改善体验，不是安全边界。员工、内部客户端、智能体三类权限均不得仅由请求体中的 ID 决定。

### ADR-03：双通道，不自动提权切换

企业连接和 OAuth 用户连接分别配置、分别授权、分别记录能力。业务操作开始时确定连接，并写入执行记录。腾讯拒绝后不得自动换成管理员连接重试。人工改用另一连接属于一次新授权决策，不继承原失败请求的隐含权限。

### ADR-04：REST / MCP 共用服务

入口只负责协议解析、认证上下文和 DTO（接口数据结构）转换。授权、会议创建、资源读取、内容下载、幂等和审计均调用同一组服务。禁止通过本机 HTTP 自调用代替共用服务层，避免重复校验逻辑和传递原始令牌。

### ADR-05：受限签发，而非共享全能 Key

内部客户端和智能体使用 Meeting 签发的有限期令牌。应用密钥只认证调用系统，不代表任何员工。员工代理必须有真实 Backend 身份凭据或已经由员工批准的持久化委托；系统同步主体另行批准。

### ADR-06：资源来源不可丢失

内容缓存始终保留授权来源、连接和版本。相同会议经两个通道发现，不代表两条授权可相互替代。元数据去重不得合并成权限并集；一个来源撤销也不得错误删除另一独立合法来源的数据。

### ADR-07：原生结果与二次加工分离

Meeting 返回腾讯原生转写与纪要，并保存格式、模型类型、时间信息、完整性和版本；不在获取失败时用本地模型生成内容冒充腾讯纪要。后续任务识别与 OA 写入由消费系统完成。

## 5. 应用、连接与腾讯凭证

### 5.1 应用类型和字段

| 字段 | 企业自建应用 | OAuth 应用 |
|---|---|---|
| `application_type`（应用类型） | `ENTERPRISE_AKSK` | `THIRD_PARTY_OAUTH` |
| 企业标识 | 腾讯应用所属企业 ID | 腾讯应用所属企业 ID，不等于所有授权人的企业 |
| 应用标识 | 腾讯 `SdkId` | 腾讯 `sdk_id` |
| 应用密钥 | `SecretId` + `SecretKey` | 客户密钥 `secret` |
| 数据范围 | 显式记录 `enterprise`；其他类型需单独批准 | 用户实际授权 scopes 与具体接口资源范围 |
| 操作者 | 已验证的企业用户映射，管理操作使用专用管理员绑定 | 已验证的授权连接 `open_id` |
| 附加配置 | STS、Webhook、固定出口、能力探测 | 授权回调、Webhook、固定出口、用户连接 |

每个应用独立绑定生产或测试环境。更改应用类型不是编辑一个枚举值，而是创建新应用配置；有历史资源的旧配置只允许禁用或归档。

### 5.2 应用与连接关系

企业应用至少有一条企业连接，包含企业绑定、允许的系统用途和管理员操作者。普通员工创建会议时应使用经验证的员工操作者，而不是固定管理员冒充员工。

OAuth 应用对应多条用户连接。连接唯一性以本地组织、应用、授权人的 `open_id` 和绑定成员为约束；同一外部身份不能悄悄绑定到多个内部员工。冲突进入人工核对，不覆盖已有连接。

`userid`、企业微信 UserID、Backend `member_id`、OAuth `open_id` 都是不同标识体系。OAuth 的 `open_corp_id` 也不得通过字符串相等直接假定等同于自建应用 AppId；采用管理员核验的企业对应关系。[T06]

### 5.3 凭证保存规则

上游密钥及 Token 使用认证加密保存，关联 `key_id`（密钥版本）。加密主密钥由独立部署 Secret 注入，禁止写进业务数据库、Git 或镜像。生产可替换为既有密钥管理系统，但不把引入新产品作为首版前提。

下游客户端密钥、访问令牌、刷新令牌仅保存安全摘要；上游 Token 因调用需要可解密保存。两类数据不能混用存储策略。

配置 API 只返回 `configured`、指纹、更新时间、最近诊断结果，不返回密钥明文。密钥轮换、授权刷新和连接禁用均留审计。所有请求日志、APM、代理日志及异常上下文都必须脱敏。

### 5.4 企业自建应用链路

凭证校验 → 企业/应用范围确认 → 管理员身份校验 → 普通查询能力 → Webhook 验证 → STS 请求与回调 → 敏感接口测试。

AK/SK 签名在适配器集中实现；签名基于实际发送的 URI、查询串和请求体字节，不在签名后再重新序列化。使用腾讯会议文档定义的签名规则，不使用其他腾讯云产品模板。[T15]

STS 按应用和授权企业隔离。生成请求与回调分别可先到达本地：先收到回调时，安全暂存为未关联票据，待已提交的请求记录关联；未经关联、企业校验和有效期校验不得启用。新票据的乱序回调不能覆盖更新版本。

### 5.5 OAuth 链路

员工先通过 Backend 登录，在 Portal 发起“绑定腾讯会议”。服务端创建一次性授权事务，绑定当前组织、成员、应用、白名单回跳位置及不可预测的 `state`，再跳转腾讯授权页面。

回调校验 `state`、有效期、所属应用、事务状态；服务端兑换 `auth_code`，核验返回身份与企业绑定，再让已登录员工确认连接。回调地址被访问本身不是员工身份凭据。

禁止接受任意 `return_url`；使用预注册目的地标识。Token 不放在浏览器 URL，不写入 localStorage，不返回智能体。

刷新按连接加锁；依据腾讯实际返回的过期时间更新全部令牌字段和 scopes。权限收缩要同步收缩连接能力。刷新凭证失效进入 `REAUTH_REQUIRED`，不能重试风暴，也不能借用另一员工 Token。

解除连接立即使网关中的连接和相关授权不可用。“本地解除连接”与“腾讯侧撤销授权”分别显示；没有已核实的上游撤销接口时不声称已替用户在腾讯撤销，提供腾讯端处理指引。

### 5.6 连接状态与能力

连接状态：`DRAFT` → `VERIFYING` → `ACTIVE`；异常分支为 `DEGRADED`、`REAUTH_REQUIRED`、`BLOCKED`；管理动作进入 `DISABLED` / `REVOKED`。

状态不代替能力矩阵。单独记录 `meeting_query`、`meeting_create`、`corp_record_list`、`record_detail`、`transcript_read`、`minutes_read`、`download` 的 `unknown / passed / denied / not_supported`、最近验证时间和非敏感原因。

能力测试必须使用指定、授权、非敏感的测试资源。一个测试资源通过，不证明同类型的所有企业资源都可读。

## 6. 身份与下游授权

### 6.1 Principal 统一结构

每次入口认证后形成服务内部 Principal，至少包含：

| 字段 | 说明 |
|---|---|
| `org_id` | Backend 确认的当前组织，不信任请求体覆盖 |
| `actor_type` | `MEMBER`、`AGENT`、`SERVICE` |
| `user_id / member_id` | 员工主体或智能体被代表员工；系统主体不伪造员工 |
| `client_id` | 由认证客户端记录得出 |
| `agent_id / grant_id` | 智能体身份与持久化委托关联，不由工具参数自由声明 |
| `token_id / audience` | 访问令牌标识和目标服务 |
| `requested_scopes` | 已认证令牌的能力上限 |
| `policy_version` | 当前授权版本，不以令牌签发时快照永久放行 |
| `trace_id` | 服务生成或验证的追踪标识 |

角色名称、是否超管只作为身份属性，不自动转换为会议正文权限。

### 6.2 Backend 新增契约

**新增：`GET /api/v1/auth/meeting-context`。** 使用现有员工 Bearer，Backend 确认当前会话、有效组织成员关系和账号状态，返回 `user_id`、`member_id`、`org_id`、角色、启用状态与展示信息。拒绝待强制改密或不满足现有登录要求的会话。

**新增内部接口：`POST /api/v1/internal/meeting/principals/resolve`。** 仅接受 Meeting 服务身份，按已验证 grant 中的组织和成员解析当前状态；不签发员工权限，不读取会议内容，不对普通内部业务客户端开放。支持批量但限制数量。

接口使用独立服务凭据或已有 mTLS 服务身份，不共享 Backend JWT 签名密钥。本文不假定仓库已经有可直接使用的 OAuth 授权服务器。

### 6.3 三种入口认证

| 调用入口 | 凭据与身份取得 | 不能做的事 |
|---|---|---|
| Portal 管理和人工确认面 | Backend Bearer → `meeting-context` | 不能因此获得业务正文全量访问 |
| 内部 REST 业务面 | Meeting 签发、面向 REST 的令牌 | 不能拿一个客户端密钥加员工 ID 冒充员工 |
| MCP 业务面 | Meeting 签发、面向 MCP 的令牌，绑定已登记客户端/智能体委托 | 不能使用普通 Backend JWT 或腾讯 Token 直接调用 |

Portal 的业务查看同样先换取 Meeting 业务令牌；管理接口不兼做无权限的内容预览入口。

### 6.4 员工委托交换

新增 `POST /api/v1/delegations/exchange`，这是**内部私有委托交换契约**，不是腾讯 OAuth，也不宣称是通用 OAuth Token Exchange 的完整实现。

机密客户端先认证自身，在请求体提交真实、短期、可验证的 Backend `subject_token` 及所需 scopes。Meeting 实时调用 Backend 获取主体，再计算客户端允许范围与员工权限交集。请求体不接受可改变主体的 `member_id` 或 `org_id`。

该接口仅限服务器间调用；原始员工 Token 只用于一次交换与验证，不持久化、不写日志。没有真实员工凭据的无人值守服务必须改用已批准的系统主体。

### 6.5 Meeting 授权入口

为受控内部 MCP 客户端提供预注册、授权码 + PKCE（S256）、刷新和撤销；员工登录继续委托 Backend。授权 UI 显示客户端、智能体、会议范围、动作和期限，并将同意结果存入 Grant。

首版只接受预注册客户端，不开放任意动态注册或任意远程客户端元数据 URL 抓取。服务端机密客户端可使用 `client_credentials`，但只取得明确批准的系统主体范围。

下游授权路径：`/oauth/authorize`、`/oauth/token`、`/oauth/revoke`；元数据路径：`/.well-known/oauth-authorization-server` 与 `/.well-known/oauth-protected-resource/mcp`。这些全部属于 **Meeting 对内部调用方的授权**，与 `/callbacks/tencent/oauth/...` 的腾讯授权回调完全分离。

REST 资源受众与 MCP 规范 URI 分别配置，令牌不跨受众复用。授权码一次性、回调 URI 精确匹配、刷新令牌轮换并检测重复使用；撤销委托同时撤销所属令牌族。[T12]

### 6.6 授权持续有效性

初期成员状态查询不启用正向缓存。每次正文读取、下载、写入和工具调用均检查当前成员状态及当前 Grant。Backend 无法验证时，对员工/智能体业务访问失败关闭，不凭旧会话猜测放行。

后台已经获得单独批准的企业采集作业可以按系统授权继续；Webhook 只接收可信上游事件，不因员工登录服务短暂不可用而停收。对外提供内容仍遵守访问控制。

## 7. 会议权限模型

### 7.1 操作权限

| 权限编码 | 权限含义 |
|---|---|
| `meeting.read` | 读取会议元数据 |
| `meeting.content.read` | 读取许可类型的正文；资产类型过滤可限定 transcript/minutes |
| `meeting.content.download` | 下载许可类型的资料；不意味着有共享链接管理权 |
| `meeting.create.self` | 使用本人已验证身份创建 |
| `meeting.create.on_behalf` | 使用批准的目标员工身份创建 |
| `meeting.acl.manage` | 在被授予的资源范围内管理授权 |
| `meeting.application.manage` | 配置腾讯应用和连接 |
| `meeting.client.manage` | 管理内部客户端及能力上限 |
| `meeting.agent_grant.manage` | 在自身可委托范围内签发、撤销智能体授权 |
| `meeting.sync.manage` | 管理批准范围的采集作业 |
| `meeting.audit.read` | 查看脱敏审计记录 |
| `meeting.diagnostics.run` | 运行指定诊断；不自动拥有正文权限 |

正文读取不自动包含下载；下载虽可在 UI 单独控制，但资料下载本身会交付对应内容。创建、代创建、授权管理分别授予。

### 7.2 资源范围

首版必须支持：`SELF_CREATED`（可信识别的本人创建）、`EXPLICIT`（明确会议/资源授权）、`ORG_APPROVED`（经批准的组织资源范围）。

`PARTICIPATED`（参会者范围）只有在可信参会身份能关联到 Backend 成员时启用；显示名和外部访客昵称不能证明成员身份。部门层级继承不作为首版默认能力：现有身份显示字段不足以证明稳定的组织树，未完成独立合同验证前使用明确成员授权。

一个 Grant 同时记录动作、资源范围、资产类型、目标成员范围、来源用途、有效期、签发人和版本。未知范围、缺失来源和失效委托默认拒绝。

### 7.3 决策顺序

认证有效 → 当前成员/系统状态有效 → 组织一致 → 客户端能力上限 → 员工或系统 Grant → 智能体额外限制 → 资源 ACL → 来源授权用途 → 上游能力与目标资源条件。

显式拒绝优先于允许；组织隔离不能被资源授权覆盖。对不存在与不属于当前访问范围的资源，外部统一返回不泄露存在性的错误；详细拒绝原因只进入有权限的审计面。

### 7.4 来源权限与缓存

企业级应用集中采集必须有 `ingestion_grant`（采集授权），指定企业连接、资源范围和允许的保存/内部提供用途。采集凭证有权限不等于组织成员有阅读权限。

OAuth 来源默认仅限绑定员工及其被批准的智能体/业务委托。第一版不将 OAuth 私有内容自动发布为组织知识，不自动将“授权了应用”视为同意全企业分享。

缓存只能减少上游请求，不能扩大来源授权。腾讯侧的撤销不一定实时可见：源授权健康状态设置有效期，失效或发现撤销后阻断相应来源；界面展示最近验证时间，不承诺能即时感知所有腾讯端变化。

首版正文来源资格验证默认 60 秒有效；遇到明确上游拒绝立即失效。要求更强即时性的组织可设为 0 并逐次核验，代价是调用配额和可用性。文件下载前必须执行可用的上游下载资格/地址校验，不利用本地缓存绕过明确禁下载。

### 7.5 角色默认值

接入管理员只管理连接和诊断；授权管理员只在批准范围管理 ACL；员工初始无额外会议资源 Grant；智能体初始无工具业务权限；审计员不自动读取正文。组织管理员可执行有审计的初始权限配置，但系统不默认为其打开所有内容。

## 8. 内部 REST 契约

### 8.1 共通约定

版本前缀 `/api/v1`；业务 ID 使用网关内部 UUID 字符串，腾讯标识仅在适配器和受限诊断面使用。时间输入采用带时区的 RFC3339，数据库统一存 UTC；适配器负责腾讯各字段秒/毫秒单位转换。

未知参数拒绝或按合同显式忽略，不接受任意腾讯参数字典。列表先授权过滤再分页，游标与组织、主体、过滤条件及资源版本绑定，不能复用其他主体的游标。

成功与失败沿用仓库的 `code`、`error_code`、`message_key`、`message`、`data` 结构，补充 `trace_id` 与稳定的 `reason` 语义。HTTP 状态保留真实成功/错误含义，不用 200 包装所有错误。整数错误编号须在实现合同中按仓库约定分配并自动查重；消费方按本文稳定 `reason` 处理业务分支，不解析中文消息。

### 8.2 业务接口

| 方法与路径 | 必要权限 | 响应与语义 |
|---|---|---|
| `GET /me/permissions` | 有效主体 | 当前能力和授权范围摘要，不泄露别人的 ACL |
| `GET /meetings` | `meeting.read` | 本地已同步的可见资源；含同步时间、分页游标和覆盖范围说明 |
| `GET /meetings/{meeting_id}` | `meeting.read` | 元数据及各类内容状态，不隐式带正文/下载地址 |
| `POST /meetings` | self / on_behalf 创建权限 | 202，返回操作记录；可处于待确认、排队或待核对状态 |
| `GET /meetings/{meeting_id}/recordings` | `meeting.read` | 录制与文件元数据、可用动作 |
| `GET /recordings/{recording_id}/transcript` | 正文读取，类型 transcript | 分页正文、版本、完整性、下一游标 |
| `GET /recordings/{recording_id}/minutes` | 正文读取，类型 minutes | 原生纪要、来源类型、格式与版本 |
| `POST /assets/{asset_id}/download-tickets` | 下载权限及类型匹配 | 201，绑定主体和资源版本的短期许可 |
| `GET /downloads/{ticket}` | 当前下载权限与相同主体 | 私有流式传输；许可本身不替代认证 |
| `POST /sync-jobs` | 同步权限及指定范围 | 202，同步作业引用；不隐含批准所有会议 |
| `GET /jobs/{job_id}` | 作业归属或管理权限 | 当前状态、进度、非敏感失败原因 |
| `GET /operations/{operation_id}` | 创建者/授权确认人 | 创建操作状态与可见结果 |

`recording_id` 在首版业务合同中指向一个可获取转写/纪要的录制文件级资源；会议录制组另用内部 `recording_group_id`。不得把腾讯 `meeting_record_id` 与 `record_file_id` 混用。

首次访问尚未同步的会议时，系统引导发起受控同步，而不是看到空列表便宣称没有历史会议。响应提供 `sync_coverage` 与 `last_synced_at`；手工导入外部会议 ID 也必须走验证和授权流程。

### 8.3 创建请求最小结构

```json
{
  "subject": "项目周会",
  "start_at": "2026-10-20T14:00:00+08:00",
  "end_at": "2026-10-20T15:00:00+08:00",
  "host_member_id": "内部成员ID",
  "invitee_member_ids": ["内部成员ID"],
  "connection_ref": "已获准使用的连接引用",
  "business_ref": "内部业务关联号"
}
```

必须携带 `Idempotency-Key`。`host_member_id` 是目标资源参数，不是调用人身份；与当前员工不一致时必须具备明确的代创建目标授权。服务器将内部身份映射到腾讯操作者，不接受外部 `operator_id` 覆盖。

首版只承诺普通一次性会议及已登记内部成员；对外部受邀人、周期规则、个人专属会议号等参数返回明确不支持。创建是否可用取决于腾讯账号能力与实际接口结果，不根据企业套餐替每个员工预判。

### 8.4 内容响应

转写响应必须包含 `asset_version`、`content_state`、`is_complete`、段落数组及 `next_cursor`。每段保留原生段落标识、相对时间、可用的说话人标记；没有可信映射时不能把说话人昵称变成内部员工 ID。

只有整份内容完成遍历、无页缺失且版本稳定后，才能设置完整版本。用户分页读取是已验证版本上的分页，不意味着每一页都包含全文。

纪要响应保存 `provider=tencent_meeting`、`llm`、`minute_type_effective`、`text_type`、语言、内容版本和获取时间。首版默认请求原文、Markdown 和元宝纪要；默认值是产品选择，参数是否可用由腾讯能力合同确认。元宝的待办可能包含在 `minute` 正文中，`todo` 为空不表示没有内容。[T09]

### 8.5 稳定业务原因

| reason | 对调用方的含义 |
|---|---|
| `IDENTITY_UNBOUND` | 员工尚无可用腾讯身份绑定 |
| `RESOURCE_NOT_ACCESSIBLE` | 无权或不可见，不泄露资源存在性 |
| `SOURCE_GRANT_INVALID` | 取得内容的来源授权失效 |
| `UPSTREAM_REAUTH_REQUIRED` | 需要重新完成腾讯用户授权 |
| `UPSTREAM_PERMISSION_DENIED` | 本地批准但腾讯未允许本次操作 |
| `UPSTREAM_CAPABILITY_UNAVAILABLE` | 指定连接/接口不支持目标能力 |
| `CONTENT_NOT_READY` | 尚不能提供完整内容，返回可查询作业或状态 |
| `SOURCE_REMOVED` | 已确认上游资源移除，停止提供原来源内容 |
| `DOWNLOAD_NOT_ALLOWED` | 本地或上游禁止下载 |
| `CONFIRMATION_REQUIRED` | 需要可信员工确认 |
| `IDEMPOTENCY_CONFLICT` | 同一键对应不同请求 |
| `OUTCOME_UNKNOWN` | 上游写入结果不确定，禁止盲目重试 |
| `RATE_LIMITED` | 达到本地或上游配额，返回合理重试提示 |
| `IDENTITY_SERVICE_UNAVAILABLE` | 不能核验当前员工状态，失败关闭 |

### 8.6 管理与 Portal 接口

管理前缀 `/api/v1/admin`，以显式管理权限控制：应用登记/更新/禁用、凭证轮换、连接诊断、身份映射、内部客户端、ACL、智能体授权、同步策略、事件投递与审计查询。

Portal 员工确认独立使用 `/api/v1/portal/operations/{id}/confirm` 和 `/reject`，只接受经 Backend 验证的真人会话和关联确认事务；不是要求员工具有应用管理员角色。

修改权限、创建连接、轮换凭证都要有操作者、旧值摘要、新值摘要及原因。调试接口禁止返回未脱敏的 HTTP 原始请求、令牌、签名或无限制内容。

## 9. MCP 契约

### 9.1 协议面

入口为 `/mcp`，采用 Streamable HTTP。实现初始化、版本协商、客户端已初始化通知、工具列表和工具调用；输入 JSON Schema 及输出结构写入冻结合同。按协议处理通知与错误，不将 REST 外层包直接当作 JSON-RPC 报文。[T13]

每次 HTTP 请求都认证，不能把 MCP session ID 当作授权凭证。首版优先使用无会话业务状态的部署方式；业务长任务始终用持久化 `operation_id` / `job_id` 查询，不把可靠性寄托在 SSE 长连接。

仅启用已实现的协议能力；不支持的方法返回协议定义的错误，不伪造工具成功。浏览器 Origin、Host、请求大小、并发和 JSON-RPC 解析均受限制，防止未授权跨站调用或资源耗尽。

### 9.2 工具列表

| 工具 | 对应服务 | 必须限制 |
|---|---|---|
| `meeting_list` | 会议列表 | 只返回授权数据，不能透传任意操作者 |
| `meeting_get` | 会议详情 | ID 不能绕过 ACL |
| `meeting_transcript_read` | 转写分页 | 内容类型、长度与资源版本固定 |
| `meeting_minutes_read` | 原生纪要 | 不在错误时生成替代“腾讯纪要” |
| `meeting_download_request` | 下载许可申请 | 只得到受控结果，不能得到腾讯原始地址 |
| `meeting_create_prepare` | 创建操作准备 | 总是进入可信确认路径 |
| `meeting_operation_status` | 操作状态 | 仅当前委托可见，不读取其他员工操作 |

不提供 `meeting_create_confirm`、任意 HTTP 工具、凭证读取工具或权限修改工具。需要特殊无人值守自动创建时，属于另行审批的后续扩展，不通过普通智能体权限默认放开。

工具描述中的只读/风险提示不是强制授权措施。`tools/list` 可按当前能力过滤，但每次 `tools/call` 必须重查权限。授权撤销后的旧工具列表、旧 session 和旧访问令牌不能继续使用。

### 9.3 智能体数据边界

智能体授权同时限定允许的工具、会议范围、资产类型、期限和内容是否允许进入该宿主。宿主标识绑定注册客户端和授予记录，不接受工具参数声明“我是可信智能体”。

不支持的宿主认证/刷新方式要在接入页显示不兼容，不能退回共享长期全能 Token。腾讯内容仅作为数据；其中的“请调用另一个工具”“忽略权限”等文本不得变成网关执行指令。

## 10. 创建、确认与幂等

### 10.1 操作状态机

```text
PREPARED → AWAITING_CONFIRMATION → APPROVED → QUEUED → RUNNING
                  │                              ├→ SUCCEEDED
                  ├→ REJECTED                     ├→ FAILED
                  └→ EXPIRED                      └→ OUTCOME_UNKNOWN
```

经 Portal 明确表单提交的真人操作可在同一次可信交互中记录批准。内部应用代理创建默认仍需要 Portal 确认；客户端请求中的 `confirmed=true`、来源说明或模型答复不构成批准。

确认绑定规范化参数摘要、目标成员、连接、授权版本、确认人、截止时间和幂等键。参数变化必须重新准备。执行前再次检查当前权限和账号状态。

### 10.2 幂等与上游不确定性

唯一范围为组织、已认证客户端、调用主体、业务动作和幂等键。相同规范化请求返回原操作；不同请求使用同一键返回冲突。连接与最终操作者也计入规范化请求摘要，禁止通过换通道复制执行。

Worker 先持久化执行尝试，再调用腾讯。调用成功后记录外部会议 ID，写业务结果和出站事件。若发送后超时、进程崩溃或本地结果提交失败，必须进入核对流程，而不是自动再次创建。

没有腾讯明确支持的幂等或关联查询能力时，网关不能承诺上游严格 exactly-once。无法唯一核对的结果进入 `OUTCOME_UNKNOWN`，由授权人员在界面核实；只有具备明确证据后才重试、关联或结束。

内部请求接受成功、后台排队成功、腾讯会议创建成功是三个不同状态，不能统一显示“创建成功”。

## 11. 回调、同步与内部通知

### 11.1 腾讯回调路由

`GET/POST /callbacks/tencent/webhook/{receiver_id}`。`receiver_id` 用来定位应用和密钥，不单独作为认证依据。每个应用接收配置独立，避免双通道回调相互误认。

GET 验证：校验签名和参数，按腾讯规则解密验证串，3 秒内原样返回明文。POST：校验签名、解密、确认事件用途并可靠落地后，5 秒内返回 HTTP 200 和 `successfully received callback`，不能添加引号、换行或业务响应外壳。[T08]

无效签名不入业务队列；数据库未提交成功时不得回复成功。合法重复事件已持久化后可重复正确确认。重放判断必须兼容腾讯合法重试，不能只按首次到达后一次性拒绝所有重发。

### 11.2 事件处理

首版订阅 STS 票据及与录制、转写、纪要就绪/失败相关的已验证事件。具体事件字段以签名验证后的官方结构与脱敏样本固化；未知事件不触发任意业务处理。

事件可能含多条 payload，拆为可独立幂等处理的子项。优先使用稳定事件标识；缺少稳定标识时用所属接收配置、事件类别、资源和稳定负载摘要生成指纹。不能只用会议号去重。

STS 事件中的票据密文进入专用受限存储，普通事件浏览只保留关联请求号、版本和处理状态。原始密文/明文事件保留策略需同时考虑其含有的访问凭据。

### 11.3 作业模型

作业：`PENDING` → `RUNNING` → `SUCCEEDED`；可重试错误进入 `RETRYING`；永久权限/身份错误进入 `BLOCKED`；超过上限进入 `FAILED`；显式取消进入 `CANCELLED`。

使用数据库领取锁、租约到期、心跳和尝试次数。Worker 崩溃可回收过期租约；重试采用退避加随机抖动；管理重试不能自动提高权限或切换连接。

限流按腾讯应用、接口及文档要求的额外维度协调，跨全部 API 实例与 Worker 共享。外部网络超时、限流、内容未就绪、账号无权分别处理；不要对所有错误使用同一种重试。

### 11.4 同步策略

首次只补导管理员选择的时间窗，默认不自动导入所有历史媒体。后续采用 Webhook 触发加周期补偿，重复扫描小范围重叠窗口以弥补遗漏，所有处理保持幂等。

账户录制补导按不超过 31 天的窗口和接口分页限制推进。用户历史会议与未来会议使用各自接口，不能把企业录制列表当成所有会议列表。[T03、T14]

游标只在对应页和结果持久化成功后推进。上游部分失败时返回部分覆盖事实，不发布虚假的全量完成事件。

### 11.5 内容状态

会议、录制、转写、纪要分别保存状态。内容状态包含 `UNKNOWN`、`NOT_READY`、`READY`、`EMPTY`、`FAILED`、`BLOCKED`、`SOURCE_REMOVED`；只有上游明确区分时才显示“未启用”或“生成中”，不能从空字符串推测原因。

转写遍历必须检查游标前进、重复页、页缺失和版本变化。大文本中途失败不得将半份内容发布为完整版本。原生纪要和转写分别就绪，不互相冒充。

### 11.6 内部通知

内部通知使用事务发件箱，与业务状态同事务写入；投递至少一次，消费方按 `event_id` 去重。首版提供资源同步、内容就绪、创建成功/待核对、授权撤销与资源不可用事件。

默认通知只含内部资源 ID、版本、状态、时间和追踪号，不含标题、正文、密码、下载票据和腾讯 Token。发送前复核目标客户端是否有事件对应范围权限；接收通知不赋予读取权限，消费方读取时再鉴权。

内部 Webhook 目的地由管理员预登记，使用 HTTPS、目标网络允许清单及独立签名密钥。禁止请求时传任意回调 URL；防止 SSRF、重定向到私网元数据地址、DNS 重绑定和携带凭据跨主机跳转。

已向某消费方交付的资源被撤销时，可以发送仅包含其曾见过的内部资源 ID 的失效通知，不因当前正文权限失效而无法通知删除。维护投递记录用于这一场景。

## 12. 受控下载、缓存与数据生命周期

### 12.1 下载许可

下载许可绑定组织、客户端、员工/系统主体、智能体委托、资产 ID、资产版本、用途、有效期。数据库只保存随机许可的摘要。许可 URL 仍需相同身份认证，不能作为匿名持有即用链接。

创建许可前检查本地下载权限和来源可下载条件；实际下载开始、断点续传和长连接期间再次检查。首版建议每 30 秒或传输 8 MiB（先达到者）复核本地撤销状态；下一 HTTP 请求始终完整鉴权。

下载通过服务端流式读取输出，设置正确 Content-Type、安全文件名与 `Cache-Control: private, no-store`；不将整个视频读入进程内存。限制单次大小、速率、并发和总流量。

腾讯下载地址只用于服务器到上游的请求；域名、重定向和目标 IP 受检查，不能作为对内接口返回值。腾讯临时链接过期只在相同授权连接下合法重新获取，不修改共享设置绕过限制。

### 12.2 权限保证的边界

对已下载到内部应用或员工设备的文件，网关不能远程收回。已传输字节也不能在撤销后“消失”。查看权限不可能阻止人工复制已显示文字；“不允许下载”仅控制系统提供的导出路径，并不构成 DRM 保证。

对已经分发的内容使用失效通知、下游留存协议和审计闭环。界面和验收用例必须使用这些准确边界。

### 12.3 保存策略

以下为**试点建议默认值，不是法律规定或已批准的企业制度**：

| 数据 | 默认策略 |
|---|---|
| 会议/录制元数据 | 180 天 |
| 原生转写与纪要缓存 | 30 天，授权范围内按需获取 |
| 音视频 | 不主动全量复制；按需临时缓存最多 24 小时 |
| 访问审计 | 180 天，默认不含正文 |
| 普通诊断与脱敏事件负载 | 7 天 |
| STS / OAuth 临时交换材料 | 最短必要保存，过期/撤销后不可再使用 |

生产启用前由数据负责人在配置中明确保存期限、下载范围和消费系统责任；未确认不得打开组织全量采集。

业务实体按仓库约定软删除，关联查询排除软删除记录。内容字节和失效密钥材料通过受控清理/对象生命周期移除，保留无敏感内容的审计墓碑；不通过删除业务表行来规避仓库规则。备份具有独立保留周期，不能承诺主库存储清理即已清除所有备份。

### 13.1 关键唯一性与去重

应用按组织、环境、腾讯应用 ID 唯一；OAuth 外部用户标识必须连同应用解释。身份映射只允许一个有效归属，软删除后的重复创建受部分唯一索引控制。

同一组织、已核验外部企业域、腾讯 meeting_id 可用于企业会议元数据归一；企业域未知或外部 OAuth 身份不可信时，以连接域隔离，不跨连接猜测归并。会议号不是唯一主键。[T14]

内容去重可以利用哈希，但跨来源只复用字节，不共享权限。资产版本与来源映射是多对多关系，每次提供内容都必须选出仍有资格的已批准来源。

事件去重包含接收配置和子项稳定指纹；操作幂等键包含已认证组织/主体/客户端；下载许可不能跨资产版本复用。跨服务 ID 只作为外部引用，不建立 Backend 数据库外键。

## 14. 页面与交互验收

页面在现有 Portal 内实现。每个页面包含加载、空数据、权限拒绝、连接失效、上游错误和成功状态，不能只有正常流程。中文与英文文案同步接入现有 i18n。[R01、R07]

| 页面 | 必要字段/操作 | 成功反馈与异常行为 |
|---|---|---|
| 接入总览 | 应用、连接、回调、能力、同步和授权告警 | 分别显示“已配置”和“已实测”，不做单个全绿总开关 |
| 腾讯应用配置 | 类型、环境、标识、密钥替换、回调指引、出口 IP 说明 | 隐藏不适用字段；不能把 OAuth Secret 填成 AK/SK |
| 用户授权连接 | 发起授权、身份确认、scopes、刷新状态、解除连接 | 错误企业/冲突进入阻断，解除后提示上游撤销边界 |
| 员工身份映射 | Backend 成员检索、外部身份、核验来源 | 不按名字自动归属；冲突列表可人工处理 |
| 内部应用接入 | 客户端类型、能力上限、回调、负责人、轮换 | 密钥仅创建时显示一次；列出已撤销状态 |
| 员工会议权限 | 成员、动作、资产类型、会议范围、期限 | 查看/正文/下载/创建分开；显示有效权限而非只有配置值 |
| 智能体授权 | 宿主、agent、员工、工具、资源、期限 | 不允许超出员工范围；确认策略不能由 agent 改写 |
| 会议资源查看 | 可见会议、同步覆盖、录制、正文、下载 | 元数据可见不等于正文可见；展示来源与完整性 |
| 创建确认中心 | 参数、目标员工、使用连接、风险、截止时间 | 只接受真人会话；修改参数使原确认失效 |
| 调试与同步中心 | 固定测试动作、资源、作业、回调验证、重试 | 诊断本身不扩大资源权限；写操作先确认 |
| 审计与通知 | 来源、主体、授权决策、投递状态、trace | 无普通正文与密钥；受审计读取权限控制 |

### 14.1 官方工具与网关诊断

接入页提供官方调试工具入口说明、配置检查和结果登记；不自动登录腾讯控制台，不抓取其登录 Cookie，不代替用户开关未知管理 API。[T11]

官方工具验证上游能力；网关诊断验证身份映射、内部权限、来源和转换。两者结果分别保存。真实写操作一律按会修改线上资源对待，测试会议使用明显标识和批准的测试账号。

## 15. 部署、配置与可观测性

### 15.1 网络面

公网仅开放腾讯 OAuth 回调、腾讯 Webhook 以及确需对外访问的授权/确认入口。内部 REST 与 MCP 默认通过企业内网、VPN 或受控边界访问；需要公网智能体接入时只对必要协议面开放，并保留认证、限速和 Origin 检查。

使用 HTTPS 443 作为生产统一入口；应用内部端口由部署配置分配，实施前检查仓库现有分配。IP 白名单填写最终出口/NAT IP，不是每个员工 IP，也不是入口负载均衡 IP。[T02]

CORS 只接受已登记的前端来源。后台系统接入不依赖浏览器 CORS。接收腾讯回调不要求员工登录，也不暴露普通管理接口。

### 15.2 配置类别

基础环境：`DATABASE_URL`、`NODESKCLAW_BACKEND_URL`、Backend 服务认证材料、`PUBLIC_BASE_URL`、REST/MCP 资源 URI、密钥版本与主密钥引用、私有存储配置、允许来源、Worker 调度参数。

腾讯应用与用户 Token 放入受控配置数据库，不把所有企业应用塞进一个全局 `.env`。环境变量中不能同时存一组“默认腾讯管理员凭证”供所有租户隐式使用。

功能开关建议：`MEETING_ENABLED`、`MEETING_MCP_ENABLED`、`MEETING_CREATE_ENABLED`、`MEETING_CORP_SYNC_ENABLED`、`MEETING_MEDIA_DOWNLOAD_ENABLED`。首次部署全部敏感能力默认关闭，经验收后逐项启用。

### 15.3 建议首版安全默认值

| 配置 | 建议值与说明 |
|---|---|
| 下游访问令牌 | 15 分钟，刷新需重核 Grant |
| 智能体 Grant | 默认 24 小时；不自动无限续期 |
| 下游刷新凭证 | 最长 7 天，且不超过 Grant 到期；轮换、复用检测 |
| 一次性授权码 | 60 秒；与腾讯自身授权码期限分开 |
| 腾讯绑定 state | 5 分钟；一次性、安全摘要保存 |
| 创建确认 | 10 分钟，过期需重新准备 |
| 下载启动许可 | 60 秒启动期限；续传会话有单独到期与复核 |
| 员工状态正向缓存 | 0 秒 |
| 来源资格健康快照 | 正文 60 秒；明确拒绝立即失效；下载逐次上游校验 |
| 元数据列表 page_size | 默认 20、最大 100，本地分页，不改变腾讯每页限制 |
| 自动企业历史补导 | 默认关闭，由管理员选择范围 |

这些数值是待评审的工程默认值，不是腾讯 API 配额或企业合规规定。

### 15.4 迁移与进程

生产通过单独迁移任务执行 Alembic，再启动 API 与 Worker，避免多个副本竞争迁移。开发可以沿用可选择的启动迁移体验，但不能以 `create_all` 替代迁移合同。

`/health/live` 只表示进程存活；`/health/ready` 检查数据库和必要内部依赖。腾讯短时不可达属于能力降级，不应导致回调进程反复重启或丢失事件。凭证状态与真实业务权限展示在受限管理诊断页，不放入公开健康检查。

### 15.5 指标与故障处理

记录接口延迟/错误、鉴权拒绝原因计数、上游限流、STS 和 OAuth 刷新失败、回调确认耗时、队列积压、租约回收、创建待核对数量、下载流量与撤销阻断、内部通知重试。

指标标签不包含员工姓名、会议标题、正文或令牌。请求追踪使用非敏感内部 ID；外部腾讯请求标识可在受限审计中关联。

|---|---|---|

### 16.4 试点性能目标

在双方记录的测试环境、固定数据规模和稳定 Backend 条件下，本地会议元数据查询目标 P95 ≤ 500 ms；腾讯回调正常确认目标 P95 ≤ 1 秒，并始终满足腾讯超时要求。第三方内容生成耗时不计入网关本地查询指标。

不在没有数据规模、网络条件与压测报告时承诺固定 QPS、全量导入时长或上游 SLA。发布证据必须记录应用类型、测试主体、权限矩阵、测试资源、时间、trace_id 和真实结果；凭证全部遮蔽。
