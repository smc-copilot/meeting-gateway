# 腾讯会议双通道配置与联调清单

**用途：**为 `nodeskclaw-meeting` 第一版准备应用、网络、授权和验证证据。本文不是已执行记录；所有检查项初始均为“未执行”。密钥、Token、Cookie、完整签名和带凭证的下载地址不得填写到本文。

设计依据见同包 `docs/superpowers/specs/2026-10-16-nodeskclaw-meeting-v1-design.md`。下列核验是在管理员已批准的企业、应用和测试资源范围内进行，不要求扩大现有权限来追求通过。

## 1. 配置责任与边界

| 工作 | 负责角色 | 必要结果 |
|---|---|---|
| 保留现有 OAuth 应用并确认权限 | 腾讯应用管理员 | 可明确识别应用类型、测试用户和回调 |
| 新建企业级自建应用 | 腾讯企业管理员 | 企业级数据范围、可用操作者和独立 AK/SK |
| 准备回调域名、出口 IP、证书 | 运维 | 入口可达、出口可核对、不混同两类 IP |
| 提供员工与组织身份契约 | Backend 负责人 | 真实登录主体、有效成员关系、停用可查询 |
| 批准采集、查看、下载和留存范围 | 数据负责人 | 书面或系统内可审计的授权记录 |
| 执行接口与反例联调 | 开发/测试负责人 | 可追踪结果，不只看 HTTP 200 |

“企业级自建应用”是应用的数据范围，不是要求更换成腾讯会议企业版套餐。仍须验证每个具体操作者、资源和接口的条件。[T01]

## 2. OAuth 应用检查

| 编号 | 检查项 | 状态 |
|---|---|---|
| O-01 | 在腾讯应用列表确认当前应用是第三方 OAuth 应用，而不是根据相似字段推断 | 未执行 |
| O-02 | 保留现有应用，不覆盖其应用 ID、客户密钥或授权用户连接 | 未执行 |
| O-03 | 应用企业 ID、应用 ID 存入 Meeting 应用配置；客户密钥只通过安全配置通道录入 | 未执行 |
| O-04 | 明确测试环境和生产环境使用哪套配置，不能共用不受控的临时回调 | 未执行 |
| O-05 | 回调域名对应 OAuth 回调入口，不是 Webhook 事件地址或 H5 可信域名 | 未执行 |
| O-06 | 需要的权限在腾讯侧已申请/获批，员工授权后核对实际返回 scopes | 未执行 |
| O-07 | 以员工 A 完成授权，再以员工 B 授权，确认产生独立连接 | 未执行 |
| O-08 | 校验 state 重放、错误回跳、错误企业、重复身份绑定均被拒绝 | 未执行 |
| O-09 | 令牌刷新失败能要求重新授权，不会借用其他员工 Token | 未执行 |
| O-10 | 本地断开连接后不可访问；界面不误称已经自动完成腾讯侧撤销 | 未执行 |

客户密钥、OAuth 访问令牌、刷新令牌只留服务端。腾讯返回的 `open_id` 以应用为范围，不能当作全局员工号。[T02、T03]

## 3. 企业级自建应用检查

| 编号 | 检查项 | 状态 |
|---|---|---|
| E-01 | 在正确企业下创建自建应用，数据范围选择企业级 | 未执行 |
| E-02 | 单独记录企业 ID、应用 ID、SecretId；SecretKey 经安全通道录入 | 未执行 |
| E-03 | 明确企业同步使用的管理员操作者及其录制管理权限 | 未执行 |
| E-04 | 普通员工创建会议使用已验证身份，不固定用管理员冒充 | 未执行 |
| E-05 | 应用可用范围覆盖已批准的测试员工，不为调试直接扩大到全员 | 未执行 |
| E-06 | 查到一场通过腾讯客户端创建的既有会议/录制，以核验范围 | 未执行 |
| E-07 | 企业录制列表分页与时间窗口符合接口限制 | 未执行 |
| E-08 | AK/SK 签名与实际 URI、查询参数、请求体完全一致 | 未执行 |
| E-09 | 应用禁用、角色不足和错误企业均有明确失败状态 | 未执行 |
| E-10 | 接入管理员不因配置了密钥而自动拥有全部会议正文权限 | 未执行 |

企业级录制列表不支持 OAuth，不能用当前 OAuth 应用代替企业补导通道。该接口当前限流为 10 次/分钟，查询窗口不超过 31 天；这是接口限制，不是内部所有 API 的统一限制。[T04]

## 4. 网络与回调检查

| 编号 | 检查项 | 状态 |
|---|---|---|
| N-01 | 生产入口使用有效 HTTPS 证书，建议外部 443、内部服务独立端口 | 未执行 |
| N-02 | 实测网关最终公网出口 IP，并与腾讯 IP 白名单一致 | 未执行 |
| N-03 | 不把入口负载均衡 IP 或员工 IP 当成出站白名单 IP | 未执行 |
| N-04 | OAuth 回调、Webhook、未来 H5/JSAPI 域名分别配置 | 未执行 |
| N-05 | 两个应用各有独立接收配置、Token 和 EncodingAESKey | 未执行 |
| N-06 | 腾讯 GET 验证经过验签、解密，3 秒内原样返回验证明文 | 未执行 |
| N-07 | 腾讯 POST 事件可靠落地后，5 秒内正确确认且不添加 JSON 外壳 | 未执行 |
| N-08 | 错误签名、未知接收配置、数据落地失败不会被当作成功事件 | 未执行 |
| N-09 | 合法重复回调能够被正确确认，业务处理保持幂等 | 未执行 |
| N-10 | 回调入口不要求员工登录，也不暴露管理/API 密钥 | 未执行 |

POST 成功确认正文必须是 `successfully received callback`，不能加引号或换行。GET 验证返回的是解密后的验证串，二者不能混用。[T05]

## 5. STS 完整链路

| 编号 | 检查项 | 状态 |
|---|---|---|
| S-01 | 自建应用已订阅 `common.sts-token` | 未执行 |
| S-02 | 管理员调用 STS 生成接口，持久化其返回的 req_id | 未执行 |
| S-03 | 成功接收并关联该请求的票据回调 | 未执行 |
| S-04 | 票据归属、版本和到期时间正确，敏感内容不进入普通日志 | 未执行 |
| S-05 | 回调提前、重复、乱序到达不会启用错误票据 | 未执行 |
| S-06 | 新建自建应用携带 STS 调用转写详情成功 | 未执行 |
| S-07 | 去除/过期票据时产生预期拒绝，不自动切换 OAuth 绕过 | 未执行 |
| S-08 | 生成请求成功但未收到回调时，状态仍显示等待票据 | 未执行 |

STS 生成接口不是同步返回可使用 Token 的接口；OAuth 通道也不使用同一 STS 流程。[T06、T07]

## 6. 测试会议与员工矩阵

准备一场非敏感、已完成云录制、腾讯端能看到转写和智能纪要的会议。记录内部测试资源引用、创建方式、内容就绪情况，不在清单中复制会议全文或可公开使用的下载地址。

| 测试主体 | 配置权限 | 应有结果 |
|---|---|---|
| 员工 A | 可看元数据 | 能看会议，不能读正文、下载、创建 |
| 员工 B | 元数据 + 纪要读取 | 能读纪要；未授转写类型则不能读转写；不能下载 |
| 员工 C | 指定资料下载 + 本人创建 | 仅下载指定类型；不能代员工 D 创建 |
| 系统同步主体 | 批准的企业采集范围 | 能补导；不成为全员阅读凭据 |
| 只读智能体 | 被代表员工的有限期纪要授权 | 可以读取授权纪要，不能直接创建或自己确认 |
| 可预约智能体 | 有准备创建的权限 | 生成待确认操作，真人确认后才执行 |
| 停用员工 | 曾经拥有任意权限 | 当前敏感业务请求拒绝 |
| 接入管理员 | 只管理应用和诊断 | 不能自动读取所有正文 |

本地授权通过并不代表腾讯必然允许；腾讯原生内容接口仍受相应角色、资源及功能开启情况限制。[T07、T08]

## 7. 两层调试分别保存证据

**腾讯官方工具：**选择正确应用，优先执行只读查询，验证凭证、授权、操作者和具体资源。允许官方工具不代表内部业务已经经过 Meeting 权限验证。该工具支持自建和第三方应用。[T09]

**Meeting 调试台：**指定已认证内部客户端及真实员工/委托，对同一测试资源验证本地授权、来源隔离、返回格式、审计和负向权限。

| 证据字段 | 记录内容 |
|---|---|
| 测试时间 | 实际执行时间及环境 |
| 应用类型 | 企业自建 / OAuth |
| 操作主体 | 可审计的内部成员/系统引用，不记录登录凭证 |
| 资源 | 已批准的非敏感测试资源引用 |
| 动作 | 具体接口/工具及权限类型 |
| 预期结果 | 允许、拒绝、未就绪或待确认 |
| 实际结果 | 状态、稳定原因、返回完整性 |
| 追踪 | 网关 trace_id、可用的腾讯请求标识 |
| 脱敏证据 | 不含凭证与正文的日志/截图/测试报告位置 |

## 8. 发布前阻断项

任何一个条件未满足，都不应把对应能力标记为已上线：双通道分别完成真实授权测试；Backend 可核验员工停用状态；越权与跨租户测试通过；密钥/正文日志扫描通过；创建不确定结果能够核对；下载撤权行为符合规格；Webhook 持久化与重试可验证；企业采集和内容留存有批准记录。

MCP 还需核验真实协议握手、令牌受众、PKCE/授权发现、工具逐次鉴权与真人确认。仅返回一个 `tools` JSON 数组不能作为完成 MCP 的证据。[T10、T11]

企业级自建应用暂不可用时，可以验证 OAuth 通道，但必须明确企业同步未验收；OAuth 暂未获批时可以验证自建通道，但不得将双通道整体标为通过。
