# 内部系统对接联调说明（OAuth 免登录起授权）

| 项目 | 值 |
|---|---|
| 文档日期 | 2026-10-20 |
| 适用产品 | meeting-gateway |
| 身份模式 | `IDENTITY_MODE=tencent_oauth` |
| 读者 | 内部业务系统 / 前端对接方 |

## 1. 定位

meeting-gateway 是 **内部系统与腾讯会议** 的桥梁。

产品口径可写：员工通过企业微信侧完成腾讯会议授权扫码。  
技术事实：授权 URL 指向腾讯会议应用市场页 `https://meeting.tencent.com/marketplace/authorize.html`，**不是**企业微信 OAuth 接口。

本轮主链路 **不要求**员工先在网关账号密码登录。

## 2. 已停用接口

以下接口固定返回 HTTP 410：

| 接口 | 错误 reason |
|---|---|
| `POST /api/v1/auth/account-login` | `ACCOUNT_LOGIN_DISABLED` |
| `POST /api/v1/auth/exchange` | `AUTH_EXCHANGE_DISABLED` |

请改走本文第 4 节主链路。旧《部署与生态联调操作手册》中仍写 account-login / exchange 的步骤以本文为准。

## 3. 凭证分层

| 凭证 | 谁持有 | 用途 |
|---|---|---|
| 内部 `client_id` + `client_secret` | 内部系统服务端 | 起授权、换业务令牌 |
| 腾讯 OAuth `authorization_url` | 浏览器打开 | 员工扫码授权 |
| 一次性 `authorization_code` | 回跳 URL，短时有效 | 换 `mt_` |
| 网关 `mt_` access_token | 内部系统 / 前端短时持有 | 调用会议业务 REST |
| 腾讯 access/refresh token | **仅网关服务端** | 上游调用，禁止下发前端 |

## 4. 主链路

```text
1) POST /api/v1/oauth/authorizations
   Authorization: Basic base64(client_id:client_secret)
   Body: { "return_to": "https://app.example.com/meeting/callback", "application_id": "" }
   → data.authorization_url, data.transaction_id

2) 前端打开 authorization_url，员工完成腾讯会议授权

3) 腾讯回调网关 GET /callbacks/tencent/oauth/{AppId}
   → 网关建立本地成员 + ACTIVE 连接
   → 303 跳转到 return_to?connection_id=...&authorization_code=oc_...&status=ACTIVE

4) POST /api/v1/oauth/sessions
   Authorization: Basic base64(client_id:client_secret)
   Body: { "authorization_code": "oc_..." }
   → data.access_token (mt_), data.connection_id, data.member_id
   （可选）data.session_token (ms_) 供 Portal 管理面使用

5) GET /api/v1/meetings 等业务接口
   Authorization: Bearer mt_...
```

`return_to` 必须事先登记在 `TENCENT_MEETING_OAUTH_RETURN_URIS`（ENV 应用白名单）。

## 5. 取数接口（需 Bearer mt_）

常用只读：

- `GET /api/v1/me/connections`
- `GET /api/v1/meetings`
- `POST /api/v1/meeting-queries`
- `GET /api/v1/meetings/{id}`
- `GET /api/v1/meetings/{id}/recordings`
- `GET /api/v1/recordings/{id}/transcript`
- `GET /api/v1/recordings/{id}/minutes`

数据范围：当前授权员工 OAuth 范围内、网关已同步/可查询的数据，**不是**企业全量历史。

## 6. 前置条件

1. 网关 `.env`：`IDENTITY_MODE=tencent_oauth`，腾讯 OAuth 应用与 Webhook 字段齐全。
2. 腾讯后台：回调域名为网关 HTTPS；出口 IP 白名单正确。
3. 管理面已登记 Confidential 内部 client（`client_id` / `client_secret`），`allowed_scopes` 至少含 `meeting.read`。
4. `TENCENT_MEETING_ALLOWED_OPEN_CORP_IDS` 含授权返回的 `open_corp_id`，否则连接为 `CORP_MISMATCH`，不会签发 `authorization_code`。

## 7. 失败码速查

| reason | 含义 | 建议动作 |
|---|---|---|
| `ACCOUNT_LOGIN_DISABLED` / `AUTH_EXCHANGE_DISABLED` | 旧接口已停用 | 改走 OAuth 主链路 |
| `TOKEN_INVALID` | client 凭证错误 | 核对 client_id/secret |
| `STATE_INVALID` | 授权事务/一次性码无效或过期 | 重新起授权 |
| `UPSTREAM_REAUTH_REQUIRED` | 需重新授权腾讯 | 再次打开 authorization_url |
| `IDENTITY_CONFLICT` | open_id 已绑定其他成员 | 联系管理员核对 |
| `PERMISSION_DENIED` | 无权限或企业未核验 | 检查 corp 白名单与 grants |
| `RATE_LIMITED` | 起授权过频 | 降低重试频率 |

## 8. 验收清单

- [ ] `account-login` / `exchange` 返回 410
- [ ] client 起授权得到 `authorization_url`
- [ ] 扫码回调后 `return_to` 带 `authorization_code`
- [ ] `/oauth/sessions` 换得 `mt_`，`connection` 为 ACTIVE
- [ ] `GET /meetings` 在授权后可调用；未授权返回 401
- [ ] 一次性 code 不可重放

## 9. 安全边界

- 起授权与换票必须 Confidential Client，禁止匿名公开起授权。
- `authorization_code` TTL 短（默认 ≤ 60s），一次性。
- URL 与响应中不得出现腾讯 access/refresh token。
- 前端环境变量可放 `client_id`；生产环境优先由后端代持 `client_secret` 再转发起授权/换票。
