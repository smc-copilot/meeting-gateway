# 内部系统对接联调说明（OAuth 免登录起授权）

| 项目 | 值 |
|---|---|
| 文档日期 | 2026-10-21 |
| 适用产品 | meeting-gateway |
| 身份模式 | `IDENTITY_MODE=tencent_oauth` |
| 读者 | 内部业务系统 / 前端对接方 |

## 1. 定位

meeting-gateway 是 **内部系统与腾讯会议** 的桥梁。

产品口径可写：员工通过企业微信侧完成腾讯会议授权扫码。  
技术事实：授权 URL 指向腾讯会议应用市场页 `https://meeting.tencent.com/marketplace/authorize.html`，**不是**企业微信 OAuth 接口。

本轮主链路 **不要求**员工先在网关账号密码登录。

**业务前端只负责发起扫码；不负责白名单，也不负责持有 `client_secret` 换票。**  
扫码后浏览器回跳必须落在网关（`{PUBLIC_BASE_URL}/oauth/tencent/complete`），由网关直接签发 `mt_` 后再 303 到业务系统。

## 2. 已停用接口

以下接口固定返回 HTTP 410：

| 接口 | 错误 reason |
|---|---|
| `POST /api/v1/auth/account-login` | `ACCOUNT_LOGIN_DISABLED` |
| `POST /api/v1/auth/exchange` | `AUTH_EXCHANGE_DISABLED` |

请改走本文第 4 节主链路。

## 3. 凭证分层

| 凭证 | 谁持有 | 用途 |
|---|---|---|
| 腾讯 OAuth `authorization_url` | 浏览器打开 | 员工扫码授权 |
| 一次性 `authorization_code` (`oc_`) | **仅网关内部** | complete 接口消费后签发 `mt_` |
| 网关 `mt_` access_token | 网关 303 带到业务落地页 | 调用会议业务 REST |
| 腾讯 access/refresh token | **仅网关服务端** | 上游调用，禁止下发前端 |

业务对接**不需要**配置 `client_id` / `client_secret`，也不需要维护 OAuth 回跳白名单。

## 4. 主链路

```text
1) 业务前端 GET /api/v1/oauth/authorizations?continue_to=https://app.example.com/meeting/done
   无需 Authorization
   → data.authorization_url, data.transaction_id
   约束：IP 限流；continue_to 须为合法 http(s) URL。生产环境同样允许 http://localhost 与 http://127.0.0.1（可带端口）；其它 http 地址仍拒绝
   说明：浏览器 OAuth 回跳由网关写死为 {PUBLIC_BASE_URL}/oauth/tencent/complete

2) 前端只打开 authorization_url，员工完成扫码

3) 腾讯回调网关 GET /callbacks/tencent/oauth/{AppId}
   → 建立本地成员 + ACTIVE 连接，签发 oc_
   → 303 到 /oauth/tencent/complete?authorization_code=oc_...&connection_id=...&status=ACTIVE

4) 网关 GET /oauth/tencent/complete
   → 内部签发 mt_（不依赖外部 client 凭证）
   → 303 到 continue_to?access_token=mt_...&expires_in=...&connection_id=...&member_id=...&status=ACTIVE

5) 业务前端从回跳 URL 读取 access_token
   Authorization: Bearer mt_...
```

`GET /api/v1/oauth/authorizations` **不会**把 `mt_` 还给这次前端请求，只返回扫码 URL。  
`continue_to` 是扫码成功后，**浏览器被 303 带走时的落地地址**，不是起授权接口的响应字段。

### 扫码后浏览器实际打哪些接口（本地联调示例）

起授权：

```text
GET /api/v1/oauth/authorizations?continue_to=http://localhost:3000/meetings/done
→ data.authorization_url = https://meeting.tencent.com/marketplace/authorize.html?...&redirect_uri=https://copilot.superic.com:9999/callbacks/tencent/oauth/{AppId}&state=...
```

前端**只**用返回的 `authorization_url` 打开扫码页（同一浏览器窗口）。扫码成功后浏览器自己走：

```text
用户打开 authorization_url（腾讯会议应用市场授权页，产品口径可称企业微信侧扫码）
        ↓ 扫码成功
1) GET https://copilot.superic.com:9999/callbacks/tencent/oauth/{AppId}
        ?auth_code=...&state=...
   处理：用 state 找回授权事务；用 auth_code 向腾讯换 access/refresh token（只留网关）；
        按 open_id 建/复用本地成员并接管旧连接；连接置 ACTIVE；签发一次性 oc_
        ↓ 303
2) GET https://copilot.superic.com:9999/oauth/tencent/complete
        ?connection_id=...&status=ACTIVE&authorization_code=oc_...
   处理：消费 oc_，内部签发 mt_
   返回：HTTP 303，不是 JSON。参数只在 Location 查询串里：
        Location: http://localhost:3000/meetings/done?access_token=mt_...&token_type=Bearer&expires_in=...&connection_id=...&member_id=...&status=ACTIVE
        ↓ 303
3) 业务页 http://localhost:3000/meetings/done?...
   处理：从地址栏读取 access_token，再调会议 REST
```

complete 成功时 Location 查询参数：

| 参数 | 含义 |
|---|---|
| `access_token` | 网关业务令牌，`mt_` 开头 |
| `token_type` | 固定 `Bearer` |
| `expires_in` | 秒 |
| `connection_id` | 会议连接 ID |
| `member_id` | 本地成员 ID |
| `status` | 成功为 `ACTIVE` |
| `session_token` | 可选，`ms_` 开头，管理面会话 |
| `session_expires_in` | 可选 |

失败时仍 303 到同一 `continue_to`，带 `error`、`connection_id`、`status`，**没有** `access_token`。  
第 1 步若直接返回 JSON（例如事务无效），浏览器会停在腾讯回调 URL，不会到 complete / 业务页。

### 业务页如何取参

落地页必须读**当前地址栏**，不要去解析起授权接口的响应：

```javascript
const q = new URLSearchParams(window.location.search)
const token = q.get("access_token")
if (!token) {
  // 没有 mt_：看是否有 error，或是否自己提前打开了 continue_to
} else {
  // Authorization: Bearer <token>
  // 收存后尽快 history.replaceState 清掉地址栏中的令牌
}
```

### 拿不到参数的常见写法（禁止）

1. 调完 `/oauth/authorizations` 后立刻 `location.href = "http://localhost:3000/meetings/done"`  
   那是前端自己打开的空页，网关还没 303，地址栏不会有 `access_token`。
2. 路由 `router.replace("/meetings/done")` 丢掉了 `window.location.search`。
3. 用 `fetch` 调 `/oauth/tencent/complete` 当 JSON 接口。complete 只对扫码浏览器做 303，不把 `mt_` 填进起授权那次 HTTP 响应。
4. 手机扫码后在手机 WebView 打开 `http://localhost:3000/...`。localhost 是**那台设备自己**，不是开发机。必须让**打开扫码 URL 的那一个浏览器窗口**跟着 303 走完。

正确顺序：前端只打开 `authorization_url`（同一窗口）→ 扫码 → 等浏览器落到 `continue_to` → 读 `window.location.search`。

核对方式：扫码完成后看地址栏。带 `?access_token=mt_...` 却读不到，是前端没读查询串；光秃秃的 `/meetings/done`，多半是自己提前跳进了 `continue_to`。

### 职责边界

| 角色 | 负责 | 不负责 |
|---|---|---|
| 业务前端 | 起授权、打开扫码 URL、从最终回跳取 `mt_` | 白名单、换票密钥、腾讯回调域名 |
| 网关 | 固定 OAuth 回跳、内部签发 `mt_`、再跳业务 | — |
| 运维 | `PUBLIC_BASE_URL`、腾讯应用/Webhook、corp 白名单 | 为业务单独配 session client / return 白名单 |

腾讯后台回调域名只登记网关；**不要**把业务系统域名配成腾讯 OAuth redirect_uri。

## 5. 取数接口（需 Bearer mt_）

- `GET /api/v1/me/connections`
- `GET /api/v1/meetings`
- `POST /api/v1/meeting-queries`
- `GET /api/v1/meetings/{id}`
- `GET /api/v1/meetings/{id}/recordings`
- `GET /api/v1/recordings/{id}/transcript`
- `GET /api/v1/recordings/{id}/minutes`

数据范围：当前授权员工 OAuth 范围内、网关已同步/可查询的数据，**不是**企业全量历史。

## 6. 前置条件

1. 网关 `.env`：`IDENTITY_MODE=tencent_oauth`，腾讯 OAuth 应用与 Webhook 字段齐全。
2. `PUBLIC_BASE_URL` 指向网关对外地址（例如 `https://copilot.superic.com:9999`），保证 `/oauth/tencent/complete` 可被浏览器访问。
3. 腾讯后台：回调域名为网关 HTTPS；出口 IP 白名单正确。
4. `TENCENT_MEETING_ALLOWED_OPEN_CORP_IDS` 含授权返回的 `open_corp_id`，否则连接为 `CORP_MISMATCH`，不会签发 `authorization_code`。

## 7. 失败码速查

| reason | 含义 | 建议动作 |
|---|---|---|
| `ACCOUNT_LOGIN_DISABLED` / `AUTH_EXCHANGE_DISABLED` | 旧接口已停用 | 改走 OAuth 主链路 |
| `STATE_INVALID` | 授权事务/一次性码无效或过期 | 重新起授权 |
| `UPSTREAM_REAUTH_REQUIRED` | 需重新授权腾讯 | 再次打开 authorization_url |
| `IDENTITY_CONFLICT` | 非扫码链路下 open_id 已绑定其他成员 | 公共扫码会接管同一 open_id 的旧连接；Portal 登录授权仍可能冲突 |
| `PERMISSION_DENIED` | 无权限或企业未核验 | 检查 corp 白名单与 grants |
| `RATE_LIMITED` | 起授权过频 | 降低重试频率 |

## 8. 验收清单

- [ ] `account-login` / `exchange` 返回 410
- [ ] 无 Authorization 调用起授权得到 `authorization_url`
- [ ] 非法 `continue_to`（非 http(s) URL）被拒绝
- [ ] 扫码后浏览器先落在网关 `/oauth/tencent/complete`
- [ ] 网关签发后跳到业务 `continue_to`，URL 带 `access_token=mt_...`
- [ ] 业务页从 `window.location.search` 读取 `access_token`；未自行提前打开 `continue_to`
- [ ] `GET /meetings` 在授权后可调用；未授权返回 401
- [ ] 一次性 `oc_` 不可重放

## 9. 安全边界

- 起授权免 client/Bearer，仅 IP 限流 + `continue_to` 格式校验。
- 浏览器 OAuth 回跳固定在网关；业务前端不持有换票密钥。
- `authorization_code` TTL 短（默认 ≤ 60s），一次性；仅在网关 complete 消费。
- URL 与响应中不得出现腾讯 access/refresh token；`mt_` 出现在业务回跳 query，业务页应尽快收存并清理地址栏。
